## 3 Необходимые сведения

### 3.1 Изображение и вход модели

MNIST содержит 60000 обучающих и 10000 тестовых изображений цифр 0–9. Каждое изображение имеет размер 28×28 и один канал яркости. Метка — целое число от 0 до 9. Пиксели переводятся из диапазона 0–255 в 0–1 делением на 255; используйте float32.

MLP преобразует изображение в вектор из 784 признаков через Flatten. Для CNN добавляют ось канала: `(число изображений, 28, 28, 1)`. Изменение формы не добавляет новой информации, а задаёт формат входа для Conv2D.

### 3.2 Слои и обучение

Dense связывает каждый вход с каждым выходом. ReLU вводит нелинейность; Softmax на выходе выдаёт десять чисел с суммой 1. Предсказанная цифра определяется через argmax. Эти значения не следует считать гарантированно откалиброванной уверенностью модели.

Conv2D применяет одни и те же фильтры в разных участках изображения, сохраняя пространственные связи. MaxPooling2D уменьшает пространственные размеры, выбирая максимумы из локальных окон. Flatten преобразует карты признаков в вектор перед Dense. Совместное использование весов сокращает число параметров свёртки; оно не гарантирует, что любая CNN будет компактнее любой MLP или полностью устойчива к сдвигам.

Число параметров Dense со смещениями: `(число входов + 1) × число выходов`. Для Conv2D: `(высота ядра × ширина ядра × входные каналы + 1) × число фильтров`. У Pooling и Flatten обучаемых параметров нет.

L2 добавляет к функции потерь штраф за большие веса. Dropout случайно отключает часть скрытых активаций при обучении и не применяется при обычной оценке. Dropout допустим между скрытым Dense и выходным Dense; обычно его не ставят после выходного Softmax, поскольку это нарушает форму вероятностного выхода при обучении.

Оптимизатор обновляет веса по градиентам. Learning rate задаёт масштаб обновлений. Слишком большой шаг может приводить к колебаниям или расходимости, слишком малый — к медленному обучению. Точный эффект проверяют экспериментально. Эпоха — один проход по train; batch size — число примеров в одном пакете обновления.

### 3.3 Выборки и метрики

Train используется для обновления весов, validation — для выбора конфигурации, test — для итоговой проверки уже зафиксированной модели. Если выбирать параметры по test, он перестаёт быть независимой проверкой. Просматривать test после каждой эпохи для выбора модели в этой работе нельзя.

Accuracy — доля правильных ответов. Sparse categorical crossentropy измеряет качество распределения вероятностей при целочисленных метках. Поле loss в Keras может включать регуляризационные штрафы. Поэтому loss MLP с L2 и loss CNN без L2 не полностью сопоставимы. Дополнительно сравните одинаковую кросс-энтропию без штрафов.

В матрице ошибок строки соответствуют истинным цифрам, столбцы — предсказанным. Диагональ содержит правильные ответы. Для каждой цифры рассчитайте recall: число верных ответов для этой цифры, делённое на число её истинных изображений. Это и есть используемая в работе «точность распознавания по цифрам», а не общая accuracy бинарной задачи.

Рост train accuracy при ухудшении validation loss может указывать на переобучение. Один график не устанавливает причину однозначно; учитывайте объём данных, регуляризацию и случайность обучения. Разные повторы дают разные результаты, поэтому в CNN используются три фиксированных seed.

## 7 Часть 2 Свёрточная нейронная сеть

### 7.1 Данные и архитектура

Укажите N и выполните загрузку данных. Train совпадает с MLP, validation и test тоже совпадают. CNN получает массивы `(n, 28, 28, 1)` float32 с пикселями 0–1.

Таблица 2 — Параметры CNN по чётности варианта

| Слой | N нечётное | N чётное |
|---|---|---|
| Conv1 | filters=5, kernel=7, stride=2, same, ReLU | filters=10, kernel=3, stride=2, same, ReLU |
| Pool1 | 2×2, stride=2, valid | 2×2, stride=2, valid |

| Dense | 10, Softmax | 10, Softmax |

Параметр padding явно задан: `same` для свёрток, `valid` для pooling. Пространственные размеры в обоих вариантах: 28 → 14 → 7 → 7 → 3. Срез Conv2 имеет форму 7×7×число фильтров Conv2, после Pool2 — 3×3×число фильтров Conv2. Проверьте это по summary; ядро 7×7 допустимо благодаря same.

Вставьте новую кодовую ячейку после пункта 4.1 блокнота. Самостоятельно рассчитайте число параметров Conv1 и Conv2 по формуле из раздела 3.2. Выведите расчёт и `count_params()` соответствующих слоёв. Совпадение чисел подтверждает правильность расчёта; при расхождении проверьте число входных каналов и смещения. Назначение stride и padding объясните в отчёте.

### 7.2 Базовое обучение

Базовая CNN использует архитектуру своего варианта, Adam, lr=0.001, batch size 32 и 10 эпох. Выполните обучение с seed 42 и построение графиков. Функция train_run каждый раз создаёт новую сеть и оптимизатор, сохраняет логи и возвращает модель, историю и строку метрик. Test внутри этой функции не используется.

Проанализируйте графики: учится ли модель, растёт ли разрыв между train и validation, нет ли нестабильности loss. Не требуется получить определённое значение accuracy: результат зависит от N и условий обучения.

### 7.3 Серия экспериментов

Архитектура, состав данных, batch size и число эпох остаются одинаковыми. Меняются только оптимизатор и learning rate:

- Adam: 0.1, 0.001, 0.00001;
- SGD: 0.1, 0.001, 0.0001;
- оптимизатор варианта из таблицы 1: 0.1, 0.001, 0.0001.

Совпадающие пары не дублируйте. При Adam по варианту остаётся 7 уникальных конфигураций; в остальных случаях — 9. Каждая обучается с seed 42, 43 и 44, поэтому всего 21 или 27 запусков. Базовый запуск Adam=0.001, seed=42 уже выполнен и учитывается в серии. При N=1, 7, 13, 19, 25 получается 21 запуск.

Самостоятельно заполните ячейку 6.1 блокнота. Создайте список rows с baseline_row, обойдите configs и SEEDS двумя циклами, пропустите уже выполненный baseline, вызовите train_run и добавьте строку результата. После каждого запуска записывайте список в experiments_raw.csv, затем создайте DataFrame results. Не сохраняйте все обученные модели в оперативной памяти.

Проверка после самостоятельной ячейки должна подтвердить ожидаемое число строк, отсутствие дубликатов name/seed и три seed для каждой конфигурации. CSV содержит seed, оптимизатор, lr, эпохи, batch, train/validation accuracy и loss, время fit. Если метрики стали NaN или infinity, зафиксируйте расходимость; такая конфигурация не может стать лучшей.

### 7.4 Сводная таблица и выбор

Для каждого запуска используются показатели после последней, десятой эпохи, измеренные через evaluate. Для каждой конфигурации рассчитайте средние validation accuracy и loss, выборочное стандартное отклонение validation accuracy (ddof=1), средние train accuracy и время fit.

Допустимая конфигурация одновременно удовлетворяет двум условиям:

1. Средний validation loss не больше среднего validation loss baseline Adam=0.001 по трём повторам.
2. Стандартное отклонение validation accuracy не больше 0.005, то есть 0.5 процентного пункта.

Среди допустимых выбирайте максимальное среднее validation accuracy. При равенстве — меньший средний validation loss, затем имя конфигурации для воспроизводимости. Используйте все три повтора; не исключайте неудачный seed ради улучшения среднего. Если хотя бы один повтор дал нечисловые метрики, исключите конфигурацию из допуска целиком.

Если допустимых конфигураций нет, прямо укажите это и используйте baseline как запасную конфигурацию. Называть её победителем критерия в таком случае нельзя. Для итоговой оценки выбранной конфигурации используйте seed 42, а не лучший из трёх повторов. В блокноте этот запуск воспроизводится заново, если выбрана не baseline; это дополнительное обучение вне серии сравнения.

### 7.5 Итоговая оценка и сохранение

После фиксации выбора выполните evaluate на полном test, predict, матрицу ошибок и таблицу recall по цифрам. Сравните train и test accuracy; укажите проблемные пары цифр и разберите минимум три ошибки по изображениям.

Сохраните выбранную CNN в `.keras`, загрузите её и сравните прогнозы для первых 16 тестовых изображений с исходной моделью. Блокнот проверяет совпадение с численной погрешностью. CSV сохраняются в папке results_CNN_N с вашим N.

## 12 Критерии оценивания

**Максимум за работу — 20 баллов.**

| Критерий | Баллы | Условия начисления |
|---|---:|---|
| Подготовка данных и разделение выборок | 2 | 1 балл — правильные train/validation/test по варианту, одинаковые для MLP и CNN; 1 — нормализация, формы входов и отсутствие использования test при подборе. |

| Самостоятельный код и эксперименты | 6 | 2 балла — два назначенных опыта MLP, по 1 за каждый; 4 — самостоятельные ячейки CNN, полная серия уникальных пар optimizer/lr с тремя seed и корректная сводная таблица. |
| Оценка качества сравнение и анализ ошибок | 4 | 1 балл — итоговые метрики и анализ ошибок MLP; 1 — выбор CNN по validation, итоговые метрики и ошибки CNN; 2 — сравнение на одинаковых данных, recall по цифрам, параметры, время и ограничения. |

| **Итого** | **20** | |

Баллы начисляются отдельно по каждому критерию в пределах его максимума. За полное корректное выполнение начисляется максимум; за частичное — баллы только за подтверждённые выполненные элементы, с шагом 0,5 балла; за отсутствие результата — 0. Один и тот же недочёт не учитывается повторно в разных критериях.

Ошибки метода (утечка цели, подбор по test, обучение и проверка на одних объектах) обнуляют только те элементы, достоверность которых они нарушают; после исправления результат оценивается повторно. Высокая accuracy сама по себе не даёт дополнительных баллов. Неудачная гипотеза не снижает балл, если эксперимент выполнен правильно и вывод соответствует данным. Вымышленные или не подтверждённые запуском результаты не засчитываются.
